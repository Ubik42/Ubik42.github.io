# GitHub 个人主页 Shape Brief

## 页面形态

- 单页品牌入口，英文为主、中文只用于姓名与少量身份补充。
- 首屏明确写出 `AI Tool Technical Artist`，并在同一视口内展示一条可读的生产工具链，而不是技能标签或抽象 AI 装饰。
- 内容顺序：身份与方法 → 三个精选系统 → 能力形成路径 → 持续项目与公共链接。

## 视觉方向

- 现代精密工作台与个人品牌页的混合体：页面拥有明确节奏和记忆点，案例局部保留真实工具的状态语言、边界和证据密度。
- 绿色手绘头像作为识别锚点；图形母题来自 `problem → rules → AI assist → human review → DCC/engine → evidence` 的传递关系。
- 使用真实 UI 局部、协议 diff、rule heatmap 与 review signal 作为主要图像，不使用粒子、玻璃卡片、渐变文字或伪终端来表达“AI”。
- 动效由 Motion for React 负责状态切换、案例展开和关系流转；React Bits 只选择一个与证据流有关的源码效果，并提供 reduced-motion 版本。

## 内容方向

- 旗舰案例：`Production Rules Across DCC and Engine`，合并 Asset Protocol 与 Cross-DCC Rule Matrix。
- 第二案例：`Visual Review as a Reproducible Contract`。
- 第三案例：`Personal AI Workflows for Research and Presentation`。
- `MayaCraft` 作为持续项目入口；履历只解释能力来源，不做长简历。

## 公开与实现边界

- 公司经验只展示抽象方法和 synthetic/reconstructed evidence。
- 电话、微信、私有路径、内部代码与真实业务数据不进入站点。
- 实现目标为 React + TypeScript + Vite，保留 GitHub Pages 静态部署；案例内容独立为数据层，便于后续持续补充。

## 待确认

1. 采用绿色手绘头像作为主视觉身份。
2. 英文主叙事，姓名和少量身份信息保留中文。
3. 首批案例采用上述三条，不把 Asset Protocol 与 Cross-DCC 拆成两张相似卡片。

确认或修改这三个方向后，进入配色与视觉参考问答，再生成首页视觉稿。
