# 火力发电检测 Unity 数字孪生客户端

这是我在上海如为电力担任 Unity 客户端开发实习生期间参与的火力发电检测项目。主要工作不是单纯展示模型，而是把发电设备、运行状态、监测参数、告警和巡检任务组织成可以操作、可以同步数据的 Unity 数字孪生客户端；Vue / Three.js 全栈展示端是随后补充的配套交付。

![工业数字孪生项目画面](/media/projects/digital-twin.png)

> 当前公开截图与仓库来自配套 Web 展示端；公司 Unity 客户端及业务数据未公开。以下内容按个人负责范围整理，不包含公司内部接口、资产和监测数据。

## Unity 仿真与业务场景

- 使用 C# 和组件化结构组织设备、监测点、交互对象和业务服务，降低场景对象与业务数据的直接耦合；
- 编写火力发电与检测流程的仿真场景逻辑，覆盖设备启停、运行状态切换、参数变化、告警联动、巡检步骤和结果反馈；
- 以状态机和事件分发连接设备状态、场景表现与 UI，使同一份业务状态能够同步驱动动画、材质、提示和操作权限；
- 使用 ScriptableObject 管理设备和流程配置，结合 Addressables、异步加载和对象池组织大型场景资源，并通过 LOD、Profiler 检查运行时开销。

## 网络、UI 与用户输入

- 使用 HTTP / WebSocket 接入监测数据，区分初始状态快照和增量更新，处理消息解析、主线程分发、超时、断线重连与异常回退；
- 使用 uGUI 搭建设备信息、趋势监控、告警提示、巡检步骤和系统状态等界面，并让页面状态随当前设备和任务上下文更新；
- 组织键鼠选择、相机漫游、设备聚焦、场景热点和参数操作，统一输入状态，避免 UI 操作与 3D 场景交互互相抢占；
- 通过明确的数据层、业务层和表现层边界，让离线仿真数据与实时监测数据可以复用同一套客户端显示逻辑。

## 配套 Web 全栈展示端

- 新增 DigitalTwin 页面、路由配置与工业场景入口，把演示能力收拢为清晰的业务操作流程。
- 整理并导入多组 FBX 工业设备与场景资产，处理模型层级、位置、旋转、缩放和浏览器侧加载。
- 扩展 Three.js / TresJS 交互，将 TransformControls、参数面板和机械关节旋转连接起来。
- 使用 Tweakpane 与 Element Plus 组织显示参数、设备选择和工业控制按钮，让非图形开发人员也能直接调整状态。
- 处理场景初始化、选中状态、控制器切换和调试入口，使模型查看、参数修改与交互反馈形成完整闭环。

Web 端使用 Vue 3、TresJS / Three.js、Element Plus 与 Express，把 Unity 客户端之外的轻量查看、参数控制和接口联调能力整理成浏览器页面。公开仓库基于开源 icegl / TresJS 框架继续开发；通用城市、地球与数据可视化模块来自上游，我完成的是工业业务页面、设备资产接入、机械控制和交互调试部分。
